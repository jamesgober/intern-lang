# intern-lang v1.0.1 — Hash-index clustering fix

**Patch.** v1.0.1 fixes a defect in the dedup index that made structured keys,
such as numbered identifiers, quadratic to intern. It also corrects the
documentation of `intern` at the symbol-space bound. The public surface is
unchanged: no item is added, removed, or altered, and every 1.0 guarantee
still holds.

## What is intern-lang?

A string interner. It maps each distinct string to a small, copyable `Symbol`,
stores the bytes once in a contiguous backing store, and hands back integer
handles. Comparing two names then becomes an integer comparison rather than a
byte walk. It is the deduplication layer beneath the lexer and the symbol table,
and it owns interning and nothing else.

## Fixed

### Structured keys clustered in the dedup index (H03)

The 1.0.0 dedup index hashed each string with an FxHash-style multiply and no
finalizer, then took the home slot from the hash's **low** bits. A multiply
carries information only upward, so the low `k` bits of the result depended only
on the low `k` bits of the last word, which for a short string means its first
two or three bytes and its length. Keys that differ only further along therefore
shared a home slot. That covers numbered identifiers (`t0000..t7999`,
`var0000..`), generated temporaries, long qualified prefixes, and the crate's own
benchmark corpus (`identifier_number_{i}`). Linear probing then walked the whole
pile-up on every insert and lookup, so total work went quadratic.

The fix, entirely internal:

- `hash_bytes` now ends in a **xor-shift / multiply / xor-shift avalanche**, so
  every bit of the slot index depends on every byte of the string. It runs once
  per string, not per word, and uses only 64-bit operations, so 32-bit targets
  pay no widening-multiply cost.
- The fingerprint cached in each slot now comes from the **high** 32 bits, which
  the slot index does not read directly, so keys that share a home slot almost
  never share a fingerprint as well.
- Short strings are packed with **fixed-width overlapping reads** (two `u32`s
  for 4–8 bytes, three single bytes for 1–3), and a long string's partial last
  word is re-read as its final eight bytes. This replaces copying a
  variable-length tail into a zeroed buffer. The probe loop also compares bytes
  rather than `&str` slices, which skips repeated char-boundary checks.

The last two changes more than pay for the finalizer. Even on a corpus that
1.0.0 did *not* cluster, interning got faster (see the control rows below).

Average probes per present key, measured with the new test-only probe counter
(lower is better; linear probing at the load factors these sizes reach predicts
about 1.3–1.5):

| Corpus | 1.0.0 | 1.0.1 |
|---|---|---|
| `t0000..t7999` (the reported shape) | 1,151.50 | 1.46 |
| `t{i}`, 100k | 1,182.36 | 1.31 |
| `very::long::common::module::path::item_{i}`, 100k | 59.88 | 1.31 |
| `{i}_with_a_long_common_suffix_tail`, 100k | 1.31 | 1.32 |
| `identifier_number_{i}` (bench corpus), 100k | 10,608.11 | 1.30 |
| every single-byte ASCII string | 1.00 | 1.59 |

The worst single probe sequence for the bench corpus fell from 30,020 slots to
16.

### `intern` documentation at the symbol-space bound (M29)

The `Interner` docs still said a non-panicking exhaustion result was "scheduled
for a later release", although `try_intern` has shipped since 0.4.0. The rustdoc
and `docs/API.md` now state exactly what happens once all `u32::MAX` symbols are
issued:

- A string that is already interned still returns its own symbol.
- A new string is not stored, and `intern` returns the highest symbol, id
  `u32::MAX`. That symbol belongs to the **last string interned**, so it compares
  equal to that string's symbol and `resolve` returns that other string.
  Round-trip and distinctness do not hold for that one return value. The interner
  itself stays consistent, and `try_intern` reports the bound as
  `InternError::SymbolSpaceExhausted`.

The behaviour itself is **unchanged** in 1.x. Every `Symbol` value already names
a string once the space is full, so the only way to return a "names nothing"
symbol is to reserve an id. That would lower the frozen `u32::MAX` capacity and
move `try_intern`'s boundary, which a patch must not do. A test now pins the
documented behaviour, and the cleaner contract is recorded for 2.0 in
`dev/ROADMAP.md`. In practice the bound is out of reach: the span table alone
would need about 64 GiB before it is hit.

Criterion: at roughly a minute or more per iteration, ten Criterion samples
were impractical. The 1.0.0 single-run "existing" rows also built their

The README figures are re-measured from these runs. The earlier ~0.23 µs
(repeat hit) and ~0.62 µs (new string) per-string numbers were measuring the
clustering defect, because the 1024-string bench corpus was itself clustered.
The 8-thread `ConcurrentInterner` figure in the README is corrected from ~4× to
~2.3× single-thread throughput. The ratio fell because the single-thread path
got much faster, so per-iteration thread spawning now dominates that bench.

## Tests and benches added

- A test-only probe counter (`#[cfg(test)]`, re-walks the probe sequence, so
  the shipping hot path has no counter).
- Bounded-probe tests (average hit ≤ 3.0, average miss ≤ 10.0, worst sequence
  ≤ 128) for:
  - 100k numbered and zero-padded numbered ids
  - 100k common-prefix and common-suffix ids
  - the 100k bench corpus
  - every one- and two-byte ASCII string
  - 12k strings of about 1 KiB
- The named regression test `h03_numbered_identifiers_do_not_cluster`.
- A property test over arbitrary `{prefix}{counter}{suffix}` families.
- A test that every byte position reaches the hash at lengths 0–24.
- A full-width collision check on the structured corpora.

With the finalizer removed, six of the new tests fail, so they catch the
regression they are named for.

Benches added: `scale_intern_new` and `scale_intern_existing` (10k / 100k / 1M ×
numbered, prefixed, bench-corpus, and pseudo-random corpora) and
`short_identifiers` (hit and miss).

## Breaking changes

**None.** The public API, every documented guarantee, and symbol id assignment
(sequential, in interning order) are unchanged. Only internal hash values and
slot layout differ, and neither is observable through the API.

## Verification

Run green on **Windows x86_64** against Rust stable 1.95 and MSRV 1.85. The
Linux and newest-toolchain gates run centrally before release.

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

`cargo clippy --all-targets --no-default-features` previously failed: the
concurrent integration tests and the bench suite import the `std`-only
`ConcurrentInterner`. `tests/concurrent.rs` is now compiled only with `std`, and
the bench target declares `required-features = ["std"]`. No library code is
involved.

Counts at this tag:

- `--all-features`: 85 tests (37 unit, 22 integration/property, 26 doctests).
- Default features: 80 tests (the 5-test `serde` suite needs its feature).
- `--no-default-features`: 60 tests (32 unit, 12 integration/property,
  16 doctests). The `std`-only concurrent tests and the `serde` suite are
  compiled out.

## What's next

The 1.x line stays additive. Recorded in `dev/ROADMAP.md`:

- **1.1.0:** `Clone`, iteration, and `serde` for `Interner` (the remainder of
  M29). These are new API, so they cannot ship in a patch. Also an optional
  caller-seeded constructor, because the hash is unkeyed. This release fixes
  *accidental* clustering. It does not stop deliberately crafted collisions.
- **2.0:** a contract for `intern` at the symbol-space bound that never returns
  another string's symbol.

## Installation

